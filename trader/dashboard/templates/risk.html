How risk gets enforced

Every signal returned by a strategy passes through the risk manager before becoming an order. The pipeline is:

  1. Kill switch. If engaged, the tick exits with no orders.
  2. Daily loss check. If equity has fallen more than the cap from start-of-day, the bot flattens all positions and engages the kill switch.
  3. Per-symbol cap. Each signal's target_pct is compared against max_position_pct; rejected if it would breach.
  4. Cash buffer. Aggregate exposure across all signals is checked against 1.0 − min_cash_buffer_pct; the whole tick is rejected if it would breach.
  5. Idempotent submit. Each order gets a unique client_order_id stored in SQLite, so a crash mid-tick won't double-submit on restart.

The same risk caps (1, 3, 4) are applied inside backtests when you run python -m trader backtest — so backtest performance reflects what live execution would actually do. Use --no-risk to compare the unconstrained version.
